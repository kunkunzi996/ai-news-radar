# AI 看板采集节点迁移至 NUC 实施计划

> 状态：DRAFT v1.0（仅计划，尚未授权真实采集或任务切换）
> 日期：2026-07-26
> 任务类型：部署迁移 / 采集链路验收
> 适用项目：AI News Radar（个人订阅聚合器）

## 1. 最终目标

把原先由旧电脑执行的 AI 看板采集任务迁到 NUC，使 NUC 成为唯一的采集节点。

迁移完成的定义是：NUC 能在本机重新登录、独立采集、向既有私有 Bridge 推送脱敏后的新结果，GitHub Actions 与网页能消费新结果；随后旧电脑的采集任务只停用、不删除。

## 2. 已确认的产品决定

1. **不迁移历史采集数据。** 不手动复制旧电脑的归档、看板 JSON、旧状态文件、缓存或旧 MediaCrawler 导出；NUC 从新的采集结果开始建立自己的运行状态。
2. **不迁移 Cookie 或浏览器登录态。** 抖音、微信及其它需要登录的平台，都由用户在 NUC 本机重新登录。
3. **不删除旧电脑资源。** 旧电脑的任务、数据、浏览器环境和 Bridge 工作区先保留，直到 NUC 的完整链路验收通过。
4. **不复用 OMNIA 工作台迁移脚本或目录。** 本计划只处理 AI 看板采集节点，与工作台数据迁移无关。

## 3. 范围

### 本计划要做

- 在 NUC 核对并使用 AI 看板主仓库、MediaCrawler、微信公众号 sidecar、抖音 Bridge、微信 Bridge 五个组件。
- 让 NUC 使用其本机新建的浏览器登录环境，生成新的抖音/微信采集结果。
- 仅通过既有 Git / Bridge 同步代码和允许推送的脱敏采集结果。
- 验证新结果能被本地看板、GitHub Actions 与网页消费。
- 完整验收后，创建或启用 NUC 采集任务，并停用旧电脑的同类任务。

### 本计划明确不做

- 不复制旧电脑的 `data/*.json`、历史归档、缓存、旧 JSONL 或旧采集状态。
- 不复制 Cookie、浏览器 Profile、私密 OPML、本地私有配置、Token、密码或日志。
- 不删除旧电脑任务、旧数据、旧浏览器目录、旧 Bridge 历史或任何 NUC 文件。
- 不修改采集业务代码、公开网页、GitHub Actions 配置或信源策略；发现代码问题时另开修复任务。
- 不让旧电脑和 NUC 在同一采集窗口对同一链路并发运行。

## 4. 目标架构

```text
NUC 本机重新登录
        │
        ▼
MediaCrawler / 微信 sidecar 采集
        │  仅产生新的公开字段结果
        ▼
私有 Bridge 仓库
        │  GitHub Actions 只读消费
        ▼
AI 看板静态数据与网页

旧电脑：保留为回退节点，直到 NUC 切换验收通过
```

边界说明：

| 层 | 负责什么 | 不负责什么 |
| --- | --- | --- |
| NUC 浏览器环境 | 用户本机重新登录、维持新登录态 | 导出或复制旧电脑 Cookie/Profile |
| MediaCrawler / 微信 sidecar | 采集并导出新的结果 | 保存到公开主仓库的私密登录信息 |
| 私有 Bridge | 保存允许同步的脱敏 JSONL、提供 Actions 消费 | 保存 Cookie、账号密码、原始浏览器数据 |
| AI 看板主仓库 | 读取 Bridge / 公开来源，生成网页数据 | 直接读取 NUC 浏览器 Profile 或私密目录 |
| 旧电脑 | 切换前的既有采集与回退依据 | 与 NUC 并行重复采集 |

## 5. 分阶段执行

### 阶段 0：范围冻结与保护

**只做：**

- 保留旧电脑的所有采集任务和运行数据。
- 保留 NUC 已恢复的仓库、依赖和浏览器环境。
- 明确不导入旧历史数据，也不复制登录态。
- 确认任何真实采集都避开旧任务的运行窗口，防止两个节点同时向同一 Bridge 写入。

**通过条件：** 本计划已确认；没有数据复制、没有删除、没有任务切换。

### 阶段 1：NUC 抖音采集入口只读诊断

**目的：** 先证明 NUC 能正确启动并接收采集脚本退出码，不能仅凭“命令曾执行”判断采集成功。

**只读检查：**

1. 核对抖音采集脚本的版本、PowerShell 语法和参数契约。
2. 用无副作用子进程验证父终端可收到退出码。
3. 只读取脱敏元数据，检查状态文件、锁、临时 owner 痕迹和上次调用是否有多行续行问题。
4. 不回显原始日志、Cookie、账号标识、作品正文或私密目录内容。

**通过条件：** 脚本可解析、参数完整、退出码可被父终端正确接收，且没有并发锁冲突。

**失败处理：** 停在诊断结论；不重试真实采集、不修改代码、不删除锁或状态文件。若确认是脚本或环境缺陷，另开最小修复计划。

### 阶段 2：NUC 独立就绪

**只做：**

1. 只读确认五个组件的 Git 工作区、依赖和本机监听状态符合各自的既有说明。
2. 在 NUC 本机由用户完成抖音、微信所需登录；验收只记录 `logged_in` / `valid` 之类状态，不读取或导出 Cookie。
3. 在每次真实采集前查询 Bridge 实时远端；若 NUC 本地落后，只允许快进同步，不允许覆盖、强推或把旧数据倒回去。
4. 使用代码受管的线上信源配置。私有本地订阅或 OPML 如需使用，另行在 NUC 手工配置，不从旧电脑复制。

**通过条件：** NUC 的登录检查通过，Bridge 工作区干净且与实时远端关系明确。

### 阶段 3：首次 NUC 抖音真实采集

**前置授权：** 必须由昆昆子单独确认。此步骤会生成新采集结果，并可能向私有 Bridge 推送新提交。

**执行规则：**

- 只运行一条受控的前台命令，不使用多行反引号续行、后台启动器或首跑 offscreen 模式。
- 不读取旧电脑历史 JSONL，不导入旧看板数据。
- 保持旧电脑的任务存在，但在不重叠的时段执行本次 NUC 首跑。
- 若脚本写入新 Bridge 提交，只核对状态和 Git 关系，不输出内容或凭据。

**通过条件：**

- 状态为成功，退出码为 0；所有计划中的抖音创作者均完成，失败数为 0。
- 新导出行数大于 0；没有新内容时，`completed_no_change` 也可视为采集成功。
- Bridge 工作区干净，且本地与实时远端 HEAD 一致。

### 阶段 4：看板消费链路验收

**只做：**

1. 验证 NUC 本地 AI 看板可读取新的 Bridge 结果并生成状态。
2. 验证 GitHub Actions / GitHub Pages 能消费新结果；只检查健康状态、更新时间和新增结果是否可见。
3. 不把旧归档整体覆盖到 NUC，也不以旧数据数量作为成功条件。

**通过条件：** 新采集结果从 NUC → Bridge → Actions → 网页的链路可验证；公开页面不暴露登录态或私密字段。

### 阶段 5：首次 NUC 微信真实采集

**前置授权：** 必须单独确认。微信采集同样会写入新的结果，并可能推送 Bridge。

**执行规则：**

- 用户先在 NUC 本机完成微信登录。
- sidecar 只输出允许公开消费的字段；不把授权态、Cookie 或原始会话写入 Bridge。
- 先进行一次人工受控采集，再检查状态与 Bridge；不直接开启定时任务。

**通过条件：** 状态成功、退出码为 0、登录态有效、Bridge 无未提交改动且远端关系一致。无新内容允许记为成功。

### 阶段 6：计划任务切换

**前置授权：** 必须单独确认创建/启用 NUC 任务，以及停用旧电脑任务。

**执行规则：**

1. 先确认抖音与微信的 NUC 人工首跑均通过。
2. 创建或启用 NUC 的正式任务定义，并记录触发时间、运行账户和工作目录。
3. 在同一维护窗口内，将旧电脑同类任务**停用**，绝不删除。
4. 观察至少两次 NUC 的计划触发，确认没有并发、没有重复 Bridge 写入、没有异常退出。

**通过条件：** NUC 任务两次连续成功；旧电脑任务为停用状态但仍可恢复；没有任务、数据或目录被删除。

### 阶段 7：观察期与回退

**观察期：** 保留旧电脑的代码、数据、登录环境和任务定义，不做清理。

**回退规则：**

- NUC 在尚未推送新 Bridge 结果前失败：停用 NUC 新任务，恢复旧电脑任务即可。
- NUC 已推送新 Bridge 结果后失败：不得用旧电脑历史文件覆盖 Bridge；先停止两个节点的同类采集，核对远端最新提交，再决定让哪个节点快进到该提交后恢复。
- 任何需要删除、覆盖历史数据、强推或重新创建 Bridge 的情况，均停止并另行取得授权。

## 6. 授权关卡

| 关卡 | 允许动作 | 本计划默认状态 |
| --- | --- | --- |
| A | 阶段 1 的只读诊断 | 可执行 |
| B | 首次 NUC 抖音真实采集及可能的 Bridge 推送 | 等待单独授权 |
| C | 首次 NUC 微信真实采集及可能的 Bridge 推送 | 等待单独授权 |
| D | 创建/启用 NUC 任务、停用旧电脑任务 | 等待单独授权 |
| E | 删除、覆盖历史数据、复制登录态、强推、改业务代码 | 不在本计划内，必须另开授权 |

## 7. 最终验收清单

- [ ] NUC 未导入旧电脑历史采集数据。
- [ ] NUC 未复制 Cookie、浏览器 Profile 或任何私密登录态。
- [ ] 抖音 NUC 人工首跑成功，Bridge 状态正常。
- [ ] 微信 NUC 人工首跑成功，Bridge 状态正常。
- [ ] Actions 与网页可消费 NUC 的新结果。
- [ ] NUC 正式任务连续两次成功，未发生双节点并发采集。
- [ ] 旧电脑任务已停用但未删除，旧数据和回退资源仍存在。
- [ ] 所有报告均只输出脱敏状态、计数和结论，不输出凭据、Cookie、账号标识、作品正文或原始日志。

## 8. 下一步

按本计划先执行 **阶段 1：NUC 抖音采集入口只读诊断**。它不会重跑采集、不产生新数据、不改任务；通过后再由昆昆子决定是否授权阶段 3 的首次真实采集。
