# 订阅源管理合并入公网页面实施计划

## 背景

此前「看信息」和「管订阅源」是分开的：浏览用公网 Pages（或本机静态服务），增删改查订阅源必须在本机
`127.0.0.1:8080` 的 local_server 控制台。采集流程已全部迁至 NUC 后，用户希望：**在平时浏览信息的
同一个网站里直接完成订阅源的增删改查**，且浏览设备不固定（家里/公司电脑、手机、出门设备，不限局域网）。

## 目标

- 公网 Pages 页面（`https://kunkunzi996.github.io/ai-news-radar/`）在阅读能力之外，可直接对订阅源
  做增删改查，并触发「同步到线上」。
- 管理接口部署在 NUC，经隧道以 HTTPS 公网可达；无令牌的访问者只能阅读、不能调用任何管理接口。
- 不改变现有阅读链路：Pages 静态页 + Actions 每 30 分钟刷新数据，NUC 不在线时阅读不受影响。
- 默认本机回环模式（无令牌、无隧道）行为与现状完全一致，现有测试全绿。

## 决策记录（2026-07-29 与用户确认）

| 问题 | 结论 |
| ---- | ---- |
| 浏览设备 | 各种设备、不限家庭局域网（公司电脑/手机/出门）→ 管理接口必须公网可达 |
| 管理接口鉴权 | 管理令牌（浏览器记住，每设备输一次） |
| NUC 部署通道 | 本机 codex 联通 NUC codex，借此执行远程部署 |
| 隧道方案 | **Cloudflare 命名隧道**：用户已有域名且 DNS 已在 Cloudflare；用子域名（如 `radar.<域名>`）指向 NUC，与既有工作台项目互不干扰（子域名记录独立） |

## 架构

```text
任意设备浏览器
   │  阅读：GET Pages 静态资源 + data/*.json（不变）
   │  管理：/api/* 跨域直连 NUC（带 X-Admin-Token）
   ▼
https://radar.<用户域名>  ← Cloudflare 命名隧道（cloudflared 常驻 NUC，免费、自带 HTTPS）
   ▼
NUC 127.0.0.1:8080  local_server.py（只绑回环，不暴露局域网）
   └─ env: RADAR_ADMIN_TOKEN / RADAR_TRUSTED_ORIGINS=https://kunkunzi996.github.io
```

- 服务器始终只绑 `127.0.0.1`，公网入口由 cloudflared 终结；Windows 防火墙不需要新规则，局域网也不暴露。
- cloudflared `tunnel login` 需要用户在浏览器授权一次（选 Cloudflare 账号下的该域名）。
- 备选隧道：Tailscale Funnel（域名不动时的零干扰方案）。首选 Cloudflare 命名隧道；若授权受阻再切换备选。

## 红线

1. **私密文件绝不许经隧道泄露**：公开模式（设置了 RADAR_ADMIN_TOKEN）下静态文件走白名单
   （`/`、`/index.html`、`/assets/*`、`/data/*`、`/site.webmanifest`、`/api/*`），其余一律 404。
   `sources.config.json`、`feeds/follow.opml`、`local-secrets/`、`.git/`、`node_modules/`、日志、
   `计划/`、`.venv*` 等都不在白名单。
2. **令牌只存在 NUC 计划任务环境和用户浏览器 localStorage**：不进仓库、不进日志（日志禁止打印
   Authorization/令牌头）、不进聊天截图。
3. **默认模式零变化**：未设置 `RADAR_ADMIN_TOKEN` 时，Origin 校验、静态服务、全部 API 行为与
   现状逐字一致；现有 pytest 不得改动预期。
4. **清理历史禁区、git 编排禁区、维护按钮派发禁区全部照旧**（见 CLAUDE.md），本功能不触碰
   archive 清理逻辑本身，只是让既有操作可以从公网页面触发。
5. 令牌校验用恒定时间比较；失败按来源 IP 限速（连败 10 次锁 60 秒，内存态，重启清零）。
6. CORS 只反射白名单 Origin；预检（OPTIONS）不含凭据时不得放行管理接口。

## 阶段划分

### 阶段 1：后端（scripts/radar/server + scripts/local_server.py）

- 新增环境变量：
  - `RADAR_ADMIN_TOKEN`：设置后所有 `/api/*` 请求必须带 `X-Admin-Token` 头且恒定时间匹配；
    缺失 → 401 `admin_token_required`，错误 → 403 `admin_token_invalid`。
  - `RADAR_TRUSTED_ORIGINS`：逗号分隔的额外可信 Origin（用于 Origin/Referer 校验与 CORS 反射）。
- OPTIONS 预检处理；`Access-Control-Allow-Origin` 仅反射可信 Origin，`Vary: Origin`。
- 公开模式静态白名单（见红线 1）。
- 失败限速（红线 5）。
- 默认模式回归：现有 `tests/test_local_server.py`、`tests/test_online_sources.py` 全绿。

### 阶段 2：前端（assets/js）

- `utils.js`：新增 `getAdminApiBase/getAdminToken/setAdminConnection/clearAdminConnection/apiFetch`；
  `canUseLocalBackend()` 扩展为「同源回环 或 已配置远程后台」。
- 全部 `./api/*` 调用点（约 20 处：local-collect 8、source-config 2、subscriptions 3、
  online-source-config 6、boot/others）改走 `apiFetch`。
- 设置抽屉「本地」tab 新增「远程管理后台」表单：API 地址、令牌、测试连接、断开；401 时管理面板
  顶部提示重新输入令牌。
- `index.html` 对应 `?v=` 缓存号 bump（禁区第 4 条）。

### 阶段 3：自动化测试

- 新增 pytest：令牌 401/403/放行/限速；可信 Origin 的 CORS 与预检；公开模式白名单
  （`sources.config.json`、`local-secrets/`、`.git/` 均 404）；默认模式行为不变。
- 全量 `python -m pytest -q` 绿。

### 阶段 4：真实浏览器验收（铁律）

- 本地起两个源（模拟 Pages 源 + 管理 API 源，不同端口即跨域），用浏览器工具实测：
  配置远程后台 → 读信源列表 → 新增测试 RSS → 停用 → 删除 → 核对 `config/online-sources.json`
  与 archive 不受影响（未点同步不触发清理）。
- 无令牌/错令牌时管理面板表现符合预期（提示输入令牌，不发请求风暴）。

### 阶段 5：NUC 部署（codex→NUC 通道）

1. NUC 仓库 `git pull` 到含本功能的 master。
2. 生成 48 位随机令牌；创建计划任务 `RadarAdminServer`：用户登录时启动
   `local_server.py --host 127.0.0.1 --port 8080`，环境带 `RADAR_ADMIN_TOKEN` 与
   `RADAR_TRUSTED_ORIGINS`（令牌写在 NUC 本地启动脚本，不进仓库）。
3. 安装 cloudflared；`cloudflared tunnel login`（用户浏览器授权一次）；创建命名隧道；
   `cloudflared tunnel route dns <tunnel> radar.<域名>`；config 指向 `http://127.0.0.1:8080`；
   注册为 Windows 服务常驻。
4. 验证：公网带令牌访问 `https://radar.<域名>/api/local-status` 返回 ok；不带令牌 401；
   `/sources.config.json`、`/local-secrets/...` 经隧道 404。

### 阶段 6：文档收口

- README 增「远程管理后台」章节；CLAUDE.md 增补本功能禁区（白名单/令牌/不得打印令牌）；
- PROJECT_STATE.md、HANDOFF.md 收口；本计划书保留。

## 验收标准

- 公网 Pages 页面在任意设备配置 API 地址 + 令牌后，可完成订阅源增删改查与同步到线上；
  阅读体验与之前一致。
- 无令牌或错令牌：任何 `/api/*` 都不可达；静态私密文件经隧道 404。
- 默认本机模式（无令牌）与现状完全一致，全量 pytest 绿。

## 回退

- 代码：功能由两个环境变量激活，未设置即回到原行为；合并后如需回退，revert 合并提交即可，
  不涉及 archive/配置数据迁移。
- NUC：停用 `RadarAdminServer` 计划任务并 `tailscale funnel --bg 8080` 关闭即可切断公网入口。

## 已知边界（本期不做）

- 远程模式下「刷新看板数据」刷的是 NUC 本地数据，公网页面读的是 Pages 数据；来源变更后的线上
  刷新由「同步到线上」push 触发的 Actions 完成。该语义本期不改，README 注明。
- 需要扫码/本机登录态的维护动作（抖音、微信）仍需在 NUC 本机操作，远程只能发起、无法代扫码。
- 不做多用户/多令牌；单一管理令牌。
